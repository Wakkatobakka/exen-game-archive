THE FIELD NOTES

Every record needs a trail.

This project is a companion to the Qualcomm BREW Archive and Zeebo Archive. It follows the same preservation-first philosophy, but it begins with different evidence. Each record keeps the source and its research status visible.

CURRENT EVIDENCE

46 catalog listings. As reviewed on 2026-10-29, My Abandonware's ExEn browse section displays 46 titles across four pages. Every title here links to its individual source record.

Zero inspected game packages. No original ExEn files were obtained, read, emulated, hashed, or hosted during this catalog build. We never use a website's download button as proof that a specific package is intact or compatible.

What was ExEn?

ExEn — short for Execution Engine — was a mobile game runtime developed by the French company In-Fusio. It was used on compatible feature phones, especially in the early 2000s, to distribute downloadable games. It existed alongside J2ME, BREW, and other handset platforms.

Contemporary reporting gives useful context: an August 2002 industry report discusses ExEn-equipped handsets and In-Fusio's downloadable games; a September 2002 announcement describes ExEn 2.0 on Panasonic devices; and a contemporary developer comparison documents how ExEn fit into the fragmented market.

How these 46 records were built

  • Reviewed the ExEn browse index, including its second, third, and fourth pages.
  • Recorded the exact title, ExEn-specific source-listed year, and direct game-page URL for each entry. Be aware that the year at the top of a multi-platform game page can refer to a different edition; our year comes from the ExEn index.
  • Added publisher, developer, genre, and notes only for selected entries where those details were individually reviewed. Unknowns are intentionally left blank.
  • Wrote our own descriptions. We did not copy screenshots, box art, original game files, third-party reviews, or source-site prose.
  • Marked every entry as source-listed / package not inspected. A listing is not proof of byte-level preservation, completeness, compatibility, or gameplay.

What a verified record would require

For a specific lawfully obtained ExEn package, a future reviewer can capture its original filename, byte size, SHA-256 checksum, file structure, software/version clues, evidence location, and an explicitly documented runtime test. Only after file inspection should a record's verification state change.

Some game pages cover several platforms or editions. Those are not interchangeable: the ExEn build must be identified separately from J2ME, BREW, or other releases.
