EXEN / PLATFORM HISTORY

Making games for ExEn

In-Fusio’s game platform, the phones it ran on, and the developers working with it.

The platform

ExEn stood for Execution Engine. In-Fusio built the game platform into compatible handsets; players downloaded games over the air and ran them locally. Panasonic’s European GD67 launch in September 2002 included ExEn 2.0, with colour and 3D support.[1]

Tools and distribution

In August 2002, In-Fusio opened a Developer Zone with design guidance, technical FAQs and a forum. An SDK download was announced as forthcoming. The company also offered revenue sharing and a fast-track deployment programme for original game concepts.[2]

Working at In-Fusio

Arnaud Storq, known as NoRecess, joined In-Fusio in Bordeaux around 2000. In his 2024 conversation with Dr JVtek, he recalled making small arcade games and an isometric adventure on 16 MHz hardware, with tiny monochrome displays in several resolutions.[3]

Testing on a phone

Storq remembered a large test team. A game crash could affect the handset itself, leaving the operator and phone manufacturer with a problem as well as the game company. His recollection concerns the early platform he worked on.[3]

A proposed mobile game API

In-Fusio submitted JSR 178, a proposed Mobile Game API for resource-limited Java devices. Thomas Landspurg was specification lead and Frederic Condolo the contact. The proposal covered sprites, graphics, collision handling, multiplayer facilities and 3D. The Java Community Process rejected it; it did not become an adopted standard.[4]
